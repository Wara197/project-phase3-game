# Requirement Specification: ระบบข้อมูลบอร์ดเกม

## ชื่อระบบและวัตถุประสงค์

**ชื่อระบบ:** ระบบข้อมูลบอร์ดเกม

**วัตถุประสงค์:**
พัฒนาระบบสำหรับการจัดการข้อมูลของบอร์ดเกมของร้านหรือตามห้องชมรมรวมถึงการจัดการสมาชิกที่เข้ามาใช้บริการ รวมไปถึงการเข้ามายืมและคืนของเกมที่ต้องการ เพื่อให้ผู้จัดการระบบสามารถติดตามสถานะของเกมที่โดนยืมไปได้และทำให้ผู้เข้ามาใช้บริการหาเกมที่ต้องการได้ตามที่่ผู้ใช้
ต้องการได้

**ปัญหาที่ระบบแก้ไข:**

- ร้านหรือชมรมที่มีบอร์ดเกมจำนวนมาก การจดบันทึกด้วยกระดาษหรือสเปรดชีตทำให้ข้อมูลไม่เป็นปัจจุบัน ตรวจสอบสถานะการยืม-คืนได้ยาก
- สมาชิกไม่ทราบว่าเกมใดรองรับจำนวนผู้เล่นของกลุ่มตนเอง ต้องถามพนักงานทุกครั้ง
- ไม่มีประวัติการยืม-คืนที่ตรวจสอบย้อนหลังได้ ทำให้ติดตามเกมที่หายหรือชำรุดได้ยากลำบาก

**กลุ่มผู้ใช้เป้าหมาย:**

- **สมาชิกหรือลูกค้า :** ค้นหาบอร์ดเกม ยืม-คืนเกม
- **ผู้ดูแลระบบ:** จัดการข้อมูลบอร์ดเกม จัดการสมาชิก อนุมัติ/บันทึกการยืม-คืน ดูรายงาน

## รายการ Use Case หลัก

| #   | Use Case                     | ผู้ใช้งาน           | คำอธิบาย                                                                              |
| --- | ---------------------------- | ------------------- | ------------------------------------------------------------------------------------- |
| 1   | ค้นหาบอร์ดเกมตามจำนวนผู้เล่น | สมาชิก              | สมาชิกระบุจำนวนผู้เล่นในกลุ่ม ระบบแสดงรายชื่อบอร์ดเกมที่รองรับ                        |
| 2   | ยืมบอร์ดเกม                  | สมาชิก              | สมาชิกเลือกบอร์ดเกมที่ต้องการยืม ระบบตรวจสอบว่าเกมว่างอยู่หรือไม่ แล้วบันทึกรายการยืม |
| 3   | คืนบอร์ดเกม                  | สมาชิก, ผู้ดูแลระบบ | บันทึกวันที่คืนเกม อัปเดตสถานะเกมกลับเป็น "พร้อมให้ยืม"                               |
| 4   | เพิ่ม/แก้ไข/ลบข้อมูลบอร์ดเกม | ผู้ดูแลระบบ         | จัดการข้อมูลพื้นฐานของบอร์ดเกม เช่น ชื่อเกม จำนวนผู้เล่นขั้นต่ำ-สูงสุด                |
| 5   | จัดการข้อมูลสมาชิก           | ผู้ดูแลระบบ         | เพิ่ม/แก้ไข/ลบข้อมูลสมาชิก และดูประวัติการยืมของสมาชิกแต่ละคน                         |
| 6   | ดูประวัติ/รายงานการยืม-คืน   | ผู้ดูแลระบบ         | ดูรายการยืม-คืนทั้งหมด กรองตามช่วงเวลา สมาชิก หรือบอร์ดเกม                            |

## รายการ Resource หลักและความสัมพันธ์

### Resource หลัก

| Resource     | คำอธิบาย                                         | ฟิลด์หลัก                                                             |
| ------------ | ------------------------------------------------ | --------------------------------------------------------------------- |
| `boardgames` | ข้อมูลบอร์ดเกมแต่ละเกม                           | `id`, `name`, `minPlayers`, `maxPlayers`                              |
| `members`    | ข้อมูลสมาชิก/ลูกค้าที่สามารถยืมเกมได้            | `id`, `name`, `email`, `phone`                                        |
| `borrowings` | บันทึกรายการยืม-คืนเกม (ตารางเชื่อมความสัมพันธ์) | `id`, `memberId`, `boardgameId`, `borrowDate`, `returnDate`, `status` |

### ความสัมพันธ์ระหว่าง Resource

- **`members` ↔ `boardgames`** เป็นความสัมพันธ์แบบ **many-to-many**: สมาชิก 1 คน ยืมได้หลายเกม และบอร์ดเกม 1 เกม สามารถถูกยืมโดยสมาชิกหลายคน (ในช่วงเวลาต่างกัน)
- ความสัมพันธ์แบบ many-to-many ข้างต้นถูกจัดการผ่านตารางกลาง (junction table) คือ **`borrowings`** ซึ่งมี:
  - `boardgameId` เป็น Foreign Key อ้างอิงไปยัง `boardgames.id` (**one-to-many**: 1 บอร์ดเกม มีได้หลายรายการยืม)
  - `memberId` เป็น Foreign Key อ้างอิงไปยัง `members.id` (**one-to-many**: 1 สมาชิก มีได้หลายรายการยืม)
- ฟิลด์ `status` ใน `borrowings` ใช้ระบุสถานะของรายการยืม เช่น `BORROWED` (กำลังยืมอยู่) หรือ `RETURNED` (คืนแล้ว) เพื่อให้ตรวจสอบได้ว่าบอร์ดเกมเกมใดว่างพร้อมให้ยืมในปัจจุบัน
